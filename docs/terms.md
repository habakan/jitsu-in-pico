# 用語と文書の書き方

README と `docs/` では、次の表記を使う。仕様名・コード上の識別子は翻訳しない。

| 日本語 | English | 意味・使い方 |
|---|---|---|
| 署名器 | signer / signing device | このプロジェクトが作る装置や署名機能。自プロジェクトを「ハードウェアウォレット」とは呼ばない |
| ウォレットソフト | wallet software | PSBT を作り、署名後にネットワークへ送る PC・スマートフォン側のソフト |
| シードフレーズ | seed phrase | BIP39 の mnemonic。技術仕様では `mnemonic` を使う |
| 解析器 | parser | UR を復元し、PSBT を解析して `Plan` を作る `parser.wasm` |
| 署名コア | signing core | 鍵を導出し、確認内容を組み立て、署名するネイティブコード |
| `Plan` | `Plan` | 解析器から署名コアへ渡す固定長の取引情報。型名は `plan_t` |
| ビューア | viewer | PSBT の表示と QR の送受信を行うブラウザ版。鍵を扱わない |
| UR | UR | PSBT などを複数の QR に分けて送る形式。規格名・コードでは大文字で書く |
| 実機 | device | Raspberry Pi Pico 2（RP2350）上で動く署名器 |

## 章立て

- README は「安全上の注意」「機能」「使い方」「検証」「構成」「設計・検証資料」「外部プロジェクトへの貢献」「ライセンス」の順にする。
- 手順書は、目的と前提を先に示し、手順、確認結果、制約の順に書く。
- 設計・計測記録は、対象と結論を冒頭に置き、根拠となる手順や数値を続ける。
- 見出しは内容を短く示す。「何が嬉しいか」「想定される反論と答え」のような会話調の見出しは避ける。

見出しの参考: [SeedSigner](https://github.com/SeedSigner/seedsigner) と [Krux](https://github.com/selfcustody/krux)。利用者が目的の情報へ進める見出しを使い、各プロジェクト固有の機能や主張は区別して書く。
