# 制約

この署名器が受け付けるもの、拒否するもの、実装していないものを示す。バグと仕様上の境界を見分けられるようにまとめた。ここに記載した内容でも、予想外の挙動があれば [SECURITY.md](../../SECURITY.md) の手順で報告してほしい。

## 状態

第三者のレビューを受けていない。signet でのみ確認している。[README の安全上の注意](README.md#安全上の注意) を参照。

## 取引

- **PSBT v0 のみ**（BIP174）。v2 は拒否する。
- **単署名のみ。** P2WPKH（BIP84）と P2TR key-path（BIP86）に対応する。マルチシグは未実装であり、未検証という意味ではない。
- **パスフレーズ非対応**（BIP39 の追加語）。
- 入力・出力はそれぞれ最大 **16 件**。PSBT は最大 **32,768 byte**。
- scriptPubKey は最大 **83 byte**（標準の OP_RETURN 上限。P2TR と P2WSH は 34 byte）。
- Taproot の script-path 支払い、miniscript、nLockTime の引き継ぎを超えるタイムロックには対応しない。
- 各入力に `witness_utxo` または `non_witness_utxo` が必要。両方ある場合、前トランザクションのハッシュが指定 txid と一致し、その出力が `witness_utxo` と一致することを確認する。
- 署名は**決定的**で、同じ PSBT から同じバイト列を生成する。BIP340 の `aux_rand` は Bitcoin Core、Trezor、Jade、BDK と同じくゼロ。BIP340 に明記されている通り、マルチシグを追加すると安全でなくなるため、そのときは必ず見直す。

## 署名前にデバイスが確認すること

- デバイス自身で鍵を導出し、得られた scriptPubKey と PSBT の値を比較する。申告された導出パスだけを信用しない。
- 出力を釣り銭と判定するのは、デバイスで再導出し、script が一致した場合だけ。
- 検証済みの入力額と出力額から手数料を計算し、画面に表示する。
- 確認したものと同じ plan に対してのみ署名する。`core_sign` はレビュー済み plan の SHA-256 を再計算し、異なれば拒否する。

## 確認しないこと

- **送金先アドレスが意図した相手のものかは判定できない。** 別の経路で確認すること。
- 現在の手数料相場は分からない。妥当に見える手数料でも誤っていることがある。
- ブロックチェーンを参照しないため、入力が使用済みか、`non_witness_utxo` が実際に承認された取引かは判定できない。
- anti-exfil（sign-to-contract）は実装していない。悪意あるファームウェアが nonce に偏りを加える可能性がある。再現可能ビルドと画面上の parser hash で確認できる範囲に限られる。

## 鍵とメモリ

- シードは RAM のみに保持し、フラッシュには書かない。電源を入れ直した後は SeedQR を再度読み込む必要がある。
- ロック解除中は、署名に必要なマスター鍵と chain code も RAM にある。**接続したデバッグプローブ（SWD）から読み取り可能**であることを実測した。[architecture-b.md](../architecture-b.md) を参照。実際に使うときはプローブを外すこと。
- `Lock (wipe seed)` は鍵をゼロ化する。前後の RAM ダンプで確認済み。
- mnemonic、BIP39 seed、SeedQR のペイロード、カメラ画像、導出した子鍵は使用後に消去する。署名 nonce も残らない。`tools/ram_keys.py` で確認済み。
- USB ブートローダー（BOOTSEL）に入ると SRAM 全体が消去されるため、残った鍵を読み出す経路にはならない。
- 任意に電圧異常を起こしたりチップを調査したりできる攻撃者への防御はない。署名前の署名検証と、署名セッションごとの secp256k1 コンテキスト再ランダム化で攻撃コストを上げるが、耐タンパー性を実現するものではない。

## QR とデータ転送

- アニメーション QR は UR（BCR-2020-005）の fountain encoding を使う。各フレームを QR version 8 に収め、240x240 の画面をスマートフォンで読み取れるよう、断片を 100 byte にしている。
- 前トランザクションが大きい PSBT は収まらないことがある。SegWit 入力の `non_witness_utxo` は `tools/strip_psbt.py` で削れる。faucet の入力に出力が 2,323 件ある場合、PSBT は 77KB、QR は 770 枚になった。
- デバイスの QR デコーダ quirc は、QR が画面の大部分を占めないと読み取れない。離れた場所から画面を読む用途には向かない。そのためブラウザビューアでは別のデコーダに切り替える。
- QR デコーダは信頼境界ではない。出力は解析器で解析・再検証する。

## ブラウザビューア（[jitsu-in の例](https://github.com/habakan/jitsu-in/tree/main/examples/viewer)）

- 鍵を**保持せず**、署名もしない。PSBT の確認とデータ転送用である。
- 表示内容は**正とみなさない**。基準にするのはデバイスの画面。ビューアはデバイスの表示を再現するためのもので、代替ではない。
- デバイスと同じ `parser.wasm` を使うが、ブラウザや OS が侵害されていない保証はない。
- カメラにはセキュアコンテキストが必要。デスクトップブラウザでは `file://` が使えるが、Android Chrome では使えない。LAN 内の `http://` はどの環境でも使えない。

## ハードウェア

- 対応する基板は Raspberry Pi Pico 2（RP2350、RISC-V Hazard3）のみ。他のターゲットでは検証していない。
- セキュアエレメント、改ざん検知、暗号化ストレージ、バックアップ電源付き RAM はない。
- RP2350 のブート ROM はオープンソースではない。
- `TEST_SEED=1` でビルドすると公開済みのテストシードを選べる。このビルドで資金を扱わないこと。
